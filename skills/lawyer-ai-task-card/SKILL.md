# 律师 AI 任务卡

## 目标

在开始执行前，把“帮我处理一下”改写成一张可以交接、可以验收、可以停止的任务卡。任务卡不能替代律师判断，也不能把未发生的提交、发送、付款、归档或结案写成已完成。

## 工作流程

### 1. 判断任务类型

先把任务归入一个或多个类型：

- 识别：读取、提取、分类、建立文件地图。
- 生成：起草、改写、排版、制作清单。
- 判断：比较方案、识别风险、提出建议。
- 执行：修改文件、上传、发送、发布、授权或删除。

只要包含“执行”，就把风险等级至少设为中风险；涉及对外发送、法院或仲裁平台、付款、权限、删除、个人信息或案件秘密时，设为高风险。

### 2. 核对最低材料

核对案件或项目名称、目标文件、适用版本、截止时间、输出格式和负责审核的人。材料缺失时，不要自行补造事实；在任务卡中列出“待补材料”和可先完成的安全部分。

### 3. 填写任务卡

按 [任务卡字段规范](references/task-card-schema.md) 填写 15 个字段。每个字段使用可核验的表述，避免“尽快”“处理好”“没问题”等无法验收的词。

### 4. 划分责任

- AI：提取、生成初稿、建立对照表、暴露不确定项。
- 助理：核对文件范围、版本、页码、姓名、日期、金额和回执。
- 律师：确认事实取舍、法律判断、诉讼策略和对外提交。

不得把律师应承担的最终判断隐藏在“AI 已检查”或“助理已处理”中。

### 5. 设定完成证据

为每项任务指定真实证据，例如：目标文件路径、重新打开后的页数、平台回执号、发送记录或人工审核签字。纯对话成果可以把“对话正文＋来源范围＋未覆盖说明”作为证据，并把文件层标为 `N/A`。仅生成文件不等于已提交，仅看到上传页面不等于上传成功。

## 双状态规则

始终分开写：

- 执行状态：`NEW`、`READY`、`RUNNING`、`NEEDS_CONFIRMATION`、`BLOCKED` 或 `DONE`；
- 成果状态：`NOT_STARTED`、`REVIEW`、`PASS`、`FAIL`、`BLOCKED` 或 `N/A`。

`READY` 只表示允许开始安全范围内的工作，绝不表示成果已经完成、合同可以签署或文书可以提交。

## 停止条件

遇到以下任一情况，停止高风险部分并标记 `NEEDS_CONFIRMATION` 或 `BLOCKED`：

- 委托人、案件、目标文件或材料范围不清；
- 法律依据、金额、期限或平台状态缺少可靠来源；
- 发送、提交、付款、发布、授权或删除没有明确授权；
- 可能泄露案件秘密、个人信息、密钥或其他客户材料；
- 多人对同一任务的负责人或版本存在冲突。

## 输出格式

先输出执行状态和成果状态。安全范围的动作已全部完成时，执行状态可以进入 `DONE`；这仍不等于成果 `PASS` 或可对外使用。

随后输出完整的 15 字段任务卡，并在末尾列出：

- 开始前检查；
- 必须由律师确认的节点；
- 完成后需要保存的证据。

不得用“基本没问题”“修改后即可签”“已经审查完成”“可以直接提交”等近义表述跳过材料补齐、律师确认和验收。
